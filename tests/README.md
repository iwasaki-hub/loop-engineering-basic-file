# 自動化された合格基準

## 導入時の記入ガイド
- この基本セットには、実行可能なテストや特定のテストツールは含めていません。
- 新規開発では必要な検証環境を準備し、既存アプリでは既存テストを確認して活用します。
- 正確な実行コマンドと前提は AGENTS.md に集約し、この文書では検証方針と要件との対応を管理します。
- 未決定は `未定`、対象外は `該当なし` とします。

## プロジェクト固有の設定
- テストツール・設定ファイル：未定
- テストの配置先：未定
- テストデータ・外部依存の準備と後片付け：未定

## テストの方針
- テスト駆動の手順、修正回数の上限、承認済みテストの扱いは AGENTS.md に従う。
- 新しい振る舞いや不具合修正では、先にテストを実行して意図した失敗を確認し、最小限の実装後に再実行する。
- Node.js標準テストランナーを採用する場合は `node --test` を使用する。他の構成では AGENTS.md に実際の検証コマンドを設定する。
- requirements.md の受け入れ条件に対応するテストを作成する。
- テスト名やコメントなどに関連要件ID（例：REQ-001）を残す。
- 正常系に加え、要件に関係する異常系・境界条件・状態の保存や復元を確認する。
- 実装の内部構造をそのまま写すのではなく、利用者や呼び出し元から観測できる振る舞いを検証する。
- 不具合を修正した場合は、再発を検知できるテストを必要に応じて追加する。
- 外部サービスや実データに依存するテストでは、実行条件とデータの後片付けを明記する。

## 手動確認
見た目、使いやすさ、実機固有の動作など、自動テストで十分に確認できない項目は requirements.md に受け入れ条件を残し、実施結果を tasks.md に記録する。

## 配置
フレームワークの慣習によりテストをソース付近などに配置する場合も、この対応表から実際の場所を参照できるようにする。
